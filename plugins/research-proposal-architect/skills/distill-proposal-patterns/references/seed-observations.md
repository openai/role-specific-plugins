# De-Identified Seed Observations

These observations were distilled from one Chinese major science and technology proposal. They contain no project names, organizations, full source paragraphs, original figures, or unpublished project-specific values.

## Writing Observations

- The overall research paragraph works best when it first defines a shared problem cluster, then introduces topics in dependency order, names forward outputs and return feedback, and closes with an integrated technical system.
- Topic-level research content commonly uses three subitems: foundation/perception, modeling/collaboration, and feedback/iteration. This is useful only when it matches the science; it is not a mandatory three-box template.
- A branch route overview is compact: demand, three-stage mainline, constructed framework, and closed-loop result, followed by a direct figure reference.
- Detailed task paragraphs become credible when they move from a precise difficulty through input, method, transformation, output, and validation rather than listing methods.
- Feedback becomes technically meaningful only when evidence source, diagnosis, adjusted object, comparison, update, and rollback are distinguishable.
- “Research content” uses higher abstraction than “research scheme.” Algorithms, equations, thresholds, and named standards are concentrated in task-level technical schemes.

## Figure Observations

- An overall research-content map benefits from topic blocks plus labeled cross-topic support and feedback rather than a simple list.
- An overall technical route benefits from a stable vertical or horizontal reading path, a separate feedback layer, an application-validation band, and a representative outcome rail.
- Branch routes need multiple grammars: sequential tasks, parallel foundations with a shared feedback task, and system integration/evaluation/demonstration.
- Core mechanism figures are strongest when reduced to a central topology or a conditional router with differentiated outputs.
- Figure labels should compress prose by role; copying full sentences makes the figure unreadable.

## Source Defects Not To Reproduce

- Raster-only figures prevent object-level correction and semantic inspection.
- Inconsistent connector styles and crowded red annotations reduce hierarchy.
- Transparent backgrounds can render as black outside the source application.
- Excessive boxes and long labels force small text on an A4 page.
- Some figures use terminology close to, but not exactly matching, the prose; the plugin requires explicit claim mapping to prevent drift.

## Candidate Rules Requiring Future Samples

- Three subitems per topic is a common rhythm but should remain optional.
- A blue/green/orange semantic palette is effective for this proposal class but must not override user branding.
- Outcome rails improve overall routes when the proposal has explicit indicators; they may be unnecessary for theory-heavy proposals.
